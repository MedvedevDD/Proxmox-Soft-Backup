# Recovery Orchestrator

## Текущий этап

На этом этапе добавлен внутренний планировщик транзакции восстановления
приложения. CLI и изменение файлов на сервере пока не включены.

Модуль выполняет следующие проверки:

1. Проверяет исходный PSB-пакет.
2. Получает порядок компонентов из `recovery_order`.
3. Выбирает компоненты, для которых Preview требует запись.
4. Обнаруживает пересекающиеся пути компонентов.
5. Готовит один rollback-пакет для всей безопасной транзакции.

## Почему проверяются пересекающиеся пути

Компоненты приложения не всегда независимы. Например, у Grafana сейчас
определены пути:

- `/var/lib/grafana`
- `/var/lib/grafana/plugins`

Второй путь находится внутри первого. Последовательная замена обоих каталогов
без специальной стратегии может уничтожить результат предыдущего шага или
сделать автоматический rollback неоднозначным.

Поэтому оркестратор блокирует такую транзакцию и возвращает
`overlap_conflicts`. Это безопаснее, чем выполнять формально правильный, но
разрушительный порядок.

## Внутренний API

```python
from pathlib import Path

from psb.applications.orchestrator import (
    build_application_transaction_plan,
    prepare_application_rollback,
)

plan = build_application_transaction_plan(
    Path("/backup/production.psb"),
    "nut",
)

prepared = prepare_application_rollback(
    Path("/backup/production.psb"),
    "nut",
    Path("/backup"),
)
```

`prepare_application_rollback()` не изменяет приложение. Он только создаёт и
проверяет единый rollback-пакет.

## Следующий этап

После проверки планировщика будут добавлены:

- единый recovery lock для приложения;
- остановка служб один раз на всю транзакцию;
- последовательная установка компонентов;
- автоматический откат уже установленных компонентов в обратном порядке;
- запуск служб только после успешного завершения всей транзакции.
