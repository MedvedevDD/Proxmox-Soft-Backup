# Recovery Orchestrator

## Назначение

Оркестратор выполняет несколько компонентов одного приложения как одну
транзакцию. Порядок компонентов берётся из `recovery_order`.

## Реализованное поведение

`execute_application_transaction()`:

1. Проверяет исходный PSB-пакет.
2. Строит план в порядке `recovery_order`.
3. Блокирует транзакции с пересекающимися путями.
4. Создаёт и проверяет один rollback-пакет.
5. Распаковывает все артефакты до остановки служб.
6. Останавливает активные службы приложения один раз.
7. Устанавливает компоненты последовательно.
8. Проверяет контрольную сумму каждого компонента.
9. Выполняет `systemctl daemon-reload` для systemd-компонентов.
10. Запускает только службы, активные до операции.
11. При ошибке возвращает заменённые каталоги в обратном порядке.

## Ограничение пересекающихся путей

Grafana пока блокируется, если одновременно требуется восстановить
`/var/lib/grafana` и `/var/lib/grafana/plugins`. Путь plugins вложен в database,
поэтому для него нужна отдельная стратегия дедупликации.

InfluxDB, Telegraf и NUT имеют независимые цели и могут выполняться текущим
транзакционным исполнителем.

## Recovery lock

Транзакция использует `schema_version: 12`. Lock содержит приложение, список
компонентов, завершённые компоненты, единый rollback-пакет, состояния служб и
итоговое состояние транзакции.
